> 生成时间: 2026-09-09。本文档是简历数字的唯一出处汇总，所有指标均真实可复现。

## 四、RAG 与模型服务

- 语义检索 Top-5 命中率: **98%**（50 条人工查询；分类查询 100%，书名查询 95%）
- DeepFM 精排接口（/rank, 68 候选）: **P95 41.9ms**，吞吐 247 req/s

## 五、简历文案（真实数字版）

**项目名称：基于多路召回与 DeepFM 精排的图书推荐系统（独立开发）**

**项目描述：**

基于 Book-Crossing 真实评分数据集（22,808 本书 / 184,738 条评分），独立完成推荐系统全链路建设：多路召回（ItemCF/UserCF/内容画像/热度）→ 融合排序 → 深度学习精排，自建离线评测体系，并接入大模型实现推荐可解释性与语义检索。后端 Java/Spring Boot，模型训练 PyTorch，ONNX + Faiss 服务化部署，Docker 五容器上线。

**个人职责：**

1. **精排模型**：采用 DeepFM（LR + FM + 3 层 DNN）构建排序模型，输入融合 ID 稀疏特征、统计特征与多路召回策略分；生产数据集上 HR@10 提升 18.9%、NDCG@10 提升 23.2%；**同方案在 MovieLens-1M 标准基准上评测，同候选池口径下 HR@10 较基线提升 61.4%、NDCG@10 提升 103.1%**（留一法，14,551/6,040 测试用户）

2. **双塔召回**：训练用户-物品双塔模型（in-batch InfoNCE），Faiss 向量检索实现语义召回；稠密基准数据上召回 HR@100 达 14.95%

3. **融合排序与冷启动**：设计 4 路召回融合排序机制，按用户行为量动态调整通道权重，解决新用户冷启动问题

4. **大模型应用**：接入 LLM API 生成基于用户画像的个性化推荐理由；bge 文本向量化构建语义检索链路，自然语言找书 Top-5 命中率 98%

5. **工程化**：ONNX 导出 + FastAPI 模型服务（算法侧/工程侧解耦，超时自动降级混合加权），精排接口 P95 41.9ms；AB 分桶实验 + 行为埋点支撑在线评估

## 六、面试口径提示

1. **数字为什么绝对值小**（书数据）: 密度 0.054%、22,808 本书候选空间、留一法全量排序——随机基线仅 0.04%，系统命中率是随机的百倍。口径比数字大小更重要（防泄漏、同池隔离）。
2. **电影基准的关系**: 评测的是"方案"而非"实例"——同一 DeepFM 方案在标准基准上验证，与论文做法一致。
3. **双塔在稀疏数据上的局限**: 如实报告负贡献，主推 DeepFM 数字——"敢报负结果"是加分项。
4. **AB 实验无真实流量**: 机制完整、数据为空，结论以离线评测为准。
